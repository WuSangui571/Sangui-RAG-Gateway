# Frontend Admin Visual Smoke Automation Baseline

## Goal

Add a minimal, repeatable browser-based visual smoke baseline for the Admin unauthenticated login screen so regressions like first-viewport white blocks and `body`/`#root` background leaks after theme switching are caught automatically.

This task follows a split-role workflow:

- Codex prepares scope, PRD, Trellis context, spec research, and test plan only.
- DeepSeek implements the code changes.
- Codex later runs check / finish-work after implementation.

## Classification

Complex Task.

Reason: the visible behavior is narrow, but the implementation introduces a browser test facility and a new frontend validation command. That affects dependency choice, local/CI command stability, documentation/spec guidance, and visual assertion design.

## Scope

### In Scope

- Add a minimal browser test facility under `frontend/`, preferably Playwright.
- Cover Admin unauthenticated login page only.
- Verify default dark theme on first render.
- Toggle to light theme and verify the page background changes consistently.
- Toggle back to dark theme and verify the page background returns consistently.
- Assert computed styles for:
  - `body`
  - `#root`
  - the app frame generated by `UIPreferenceProvider`
  - the unauthenticated login wrapper in `AdminShell`
- Add a lightweight edge / viewport pixel or screenshot-based guard if practical, focused on top and outer viewport edges not showing white in dark mode.
- Add the new command to frontend validation docs, preferably `.trellis/spec/frontend/quality-guidelines.md`.
- Keep existing `npm run typecheck` and `npm run build` checks intact.

### Out of Scope

- No backend Java changes.
- No `/api/*` or `/v1/*` contract changes.
- No database, migration, Docker, Redis, MinIO, gateway, retrieval, prompt, or request-log changes.
- No visual redesign of the login page.
- No change to admin login behavior, validation, i18n copy, page navigation, or API calls.
- No new persisted UI preference keys beyond existing `sangui-admin-theme` and `sangui-admin-locale`.
- No broad end-to-end admin workflow automation in this task.
- No storing screenshots, traces, or videos in committed files unless they are intentionally ignored test artifacts.

## Existing Context

Session 32 fixed Admin login dark background consistency and recorded that automated browser visual smoke was missing because the project had no Playwright dependency and no configured browser runtime. Manual visual acceptance supplied the final evidence. This task converts that missing evidence into a repeatable frontend smoke command.

Current frontend facts:

- `frontend/package.json` currently has `dev`, `build`, `typecheck`, and `preview` scripts only.
- `frontend/src/main.tsx` wraps `App` with `UIPreferenceProvider`.
- `frontend/src/app/providers/UIPreferenceProvider.tsx` owns Ant Design `ConfigProvider`, `themeMode`, persisted UI preference keys, and `--sangui-admin-page-bg`.
- `frontend/src/styles/index.css` applies `--sangui-admin-page-bg` to `body` and `#root`.
- `frontend/src/components/layout/AdminShell.tsx` renders the unauthenticated login wrapper when `adminUserId === null`; the wrapper background uses Ant Design `token.colorBgLayout`.

## Command Contract

Add one explicit frontend visual smoke command.

Recommended command:

```bash
cd frontend
cmd /c npm run test:visual
```

Recommended implementation shape:

```text
frontend/playwright.config.ts
frontend/tests/visual/admin-login-theme-smoke.spec.ts
```

Recommended script additions:

```json
{
  "scripts": {
    "test:visual": "playwright test"
  },
  "devDependencies": {
    "@playwright/test": "<current compatible version>"
  }
}
```

Use a Playwright web server that starts the Vite dev server through the existing `npm run dev` command if stable in this repo. If that is unreliable, document and use the smallest equivalent command that serves the Vite app locally for tests.

Do not require backend services for this visual smoke. The unauthenticated login screen must be testable with frontend-only runtime.

## DOM / Assertion Contract

The test should assert visible and computed style evidence, not just that the app renders.

Required states:

| State | Setup | Expected |
|---|---|---|
| Default dark | Empty or cleared `localStorage`, open app root | `body`, `#root`, app frame, and login wrapper have dark-compatible backgrounds; top and outer viewport edges are not white. |
| Light after toggle | Click the theme toggle from unauthenticated screen | `body`, `#root`, app frame, and login wrapper have light-compatible backgrounds. |
| Dark after second toggle | Click the theme toggle again | Same dark-compatible assertions as first render. |

Required assertion points:

| Target | Suggested selector / method | Assertion |
|---|---|---|
| `body` | `document.body` | Computed `backgroundColor` matches dark/light expected value or an allowed normalized RGB value. |
| `#root` | `#root` | Computed `backgroundColor` matches the theme-owned page background. |
| App frame | first child under `#root`, or a stable test id if DeepSeek adds one only for testability | Computed `backgroundColor` matches theme-owned page background. |
| Login wrapper | stable selector/test id if needed | Computed `backgroundColor` matches Ant Design layout background for current theme, and is not white during dark mode. |
| Viewport edges | screenshot pixel sample or `elementFromPoint` + computed style at edges | Dark state must not expose white at top, left, right, or bottom viewport boundaries. |

If a stable selector is needed, prefer adding a narrow `data-testid` to existing structural wrappers. Do not change visual structure just to make testing easier.

## Validation / Error Matrix

| Scenario | Expected result | Failure boundary |
|---|---|---|
| Fresh frontend install with Playwright browsers available | `npm run test:visual` starts the app and passes dark/light/dark assertions | `visual-smoke` |
| Default theme is no longer dark | Test fails before any toggle | `theme-default` |
| `body` or `#root` leaks white in dark mode | Test fails on computed style or pixel edge assertion | `theme-background` |
| Login wrapper no longer follows dark layout background | Test fails on wrapper computed style | `login-wrapper` |
| Theme toggle does not update body/root/app frame | Test fails after light or second dark toggle | `theme-toggle` |
| Backend is not running | Visual smoke still passes because it only covers unauthenticated login | `frontend-only-runtime` |
| Browser dependency missing in CI/local environment | Command fails clearly with Playwright install/browser error; do not add silent fallbacks that mark visual smoke as passed | `browser-runtime` |

## Good / Base / Bad Cases

| Case | Expected result |
|---|---|
| Good | `npm run test:visual` starts the Vite frontend, opens the unauthenticated Admin login page, verifies default dark backgrounds across `body`, `#root`, app frame, login wrapper, toggles to light, verifies light backgrounds, toggles back to dark, verifies no white viewport edges. |
| Base | If screenshot/pixel edge checks are too brittle initially, computed style assertions for all required DOM targets must still be implemented, and the PR/spec must explicitly state pixel coverage is deferred. |
| Bad | Test only checks page text exists, snapshots the whole page without assertions, depends on backend data, hides failures with broad retries/fallbacks, changes login UX, or stores theme/runtime evidence in new persistent frontend state. |
